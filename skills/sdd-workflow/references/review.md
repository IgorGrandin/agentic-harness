# Review workflow

Review is read-only unless the user authorizes fixes.

1. Establish the intended change and review baseline.
2. Inspect the diff plus enough surrounding code to validate behavior.
3. Prioritize correctness, security, data loss, compatibility, and missing verification.
4. Report only actionable findings supported by evidence; separate uncertainty from defects.
5. Tie findings to acceptance criteria when a spec exists.
6. Summarize residual risk and coverage gaps when no findings are present.
